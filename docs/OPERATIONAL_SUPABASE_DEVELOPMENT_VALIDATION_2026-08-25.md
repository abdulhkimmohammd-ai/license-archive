# تقرير التحقق التشغيلي — Supabase Development

**التاريخ:** 25 أغسطس 2026  
**النطاق:** مشروع `License Archive – Migration Lab` وSupabase Development فقط. لا يتضمن التقرير Production أو بيانات حقيقية أو Cloudflare Deploy أو DNS أو Domains.

## النتيجة التنفيذية

اكتملت **شريحة تشغيلية انتقالية** تتعامل مع Supabase Development عبر JWT وRLS وRPC، مع بقاء MySQL/tRPC هو المسار الافتراضي وغير المعدل. أصبح بالإمكان، في وضع انتقال صريح، قراءة التراخيص والبحث والفلترة والترقيم وإضافة ترخيص وتعديل بياناته وتجديده وتغيير رقم الأرشفة وأرشفته ونقله إلى السلة واستعادته؛ وكل ذلك مستخدماً حسابات اختبار معتمدة فقط.

> **القرار:** لا يوجد أي تصريح للنشر أو لترحيل Production. تظل الصفحات والأصول التي لم تنقل متصلة عمداً بمسار MySQL/tRPC إلى أن تجتاز شريحة مستقلة من اختبارات المطابقة.

| الواجهة | أضيفت مسارات انتقال صريحة لا تغير الواجهة الأصلية ولا الترجمة أو RTL. | الوضع الانتقالي يطلب جلسة Supabase Development معتمدة؛ لا يستخدم الحسابات الحقيقية. |

## تنبيهات أمنية معروفة ومقبولة في Development

يظهر مستشار Supabase تحذيرات `SECURITY DEFINER` لجميع إجراءات RPC الإدارية والمتعمدة، بما فيها الإجراءين التشغيليين الجديدين. هذه ليست صلاحيات مفتوحة: كل دالة تثبت `search_path` وتفحص الدور وحالة الاعتماد داخل `private.assert_approved_role`، كما أثبت اختبار المستخدم العادي الرفض الفعلي. تبقى هذه التحذيرات بند مراجعة إلزامي قبل أي Production، ولا ينبغي إخفاؤها أو تحويلها إلى صلاحية مباشرة للجداول.

يظل تحذير حماية كلمات المرور المسربة ظاهراً لأن الميزة تتطلب خطة Supabase مدفوعة. ووفق توجيه مالك المشروع، لم تُرفع الخطة ولم تُطلب هذه الميزة كشرط لهذه البيئة التجريبية.

## ما لم ينتقل بعد

| المجال | الوضع الحالي | شرط الانتقال |
|---|---|---|
| لوحة التحكم والإحصائيات | ما زالت MySQL/tRPC. | إنشاء RPC إحصاءات وعقد مقارنة مؤشرات مع MySQL. |
| صفحة الأرشفة/الاستعلام المتقدم | ما زالت MySQL/tRPC. | دعم فلاتر تاريخ الأرشيف وCSV في Supabase ثم اختبار المطابقة. |
| التصدير والطباعة الرسمية وPDF وQR | لم تُنقل. | مقارنة نموذج الوزارة حرفياً على بيانات اختبار قبل تبديل مصدره؛ لا تغيير للنموذج. |
| فريق المستخدمين | ما زال MySQL/tRPC. | تصميم إدارة أدوار Supabase Auth آمنة ومراجعة منع آخر مدير من الحظر. |
| Offline Queue للتطبيق الرئيسي | ما زال MySQL/tRPC. | نقل طابور UUID ومفتاح المستخدم إلى Supabase بعد اختبار متصفح مستقل. |
| المرفقات/Storage | مؤجل عمداً. | لا تُنشأ Storage أو مرفقات في هذا المشروع إلا بموافقة مستقلة. |
| حذف نهائي | غير منقول. | لا يُنفذ قبل سياسة احتفاظ وموافقة مستقلة. |

## المخاطر والضوابط

يملك الوضع الانتقالي جلستين منفصلتين مؤقتاً: Manus للمسار التاريخي وSupabase Development للمسار الجديد. هذا مقصود لتجنب تغيير المصادقة العامة دفعة واحدة. قبل تحويل المسار الافتراضي يجب اعتماد تصميم Supabase Auth الكامل، ودعوة حسابات اختبار فقط، ومسار خروج واستعادة آمن.

لا تستخدم صفحة التفاصيل الانتقالية الطباعة الوزارية أو PDF أو المرفقات؛ هذا يمنع تقديم وظيفة تبدو مكتملة بينما مصدر بياناتها لم يختبر بعد. كما أن المستخدم العادي لا يرى وظائف إدارية، لكن الحماية الأساسية لا تعتمد على هذا الإخفاء، بل على RLS وRPC.
