# تشخيص استكمال License Archive Development

**النطاق:** نسخة Development الحالية فقط، دون Publish أو Deploy أو Migration أو تعديل DNS/Domain/Production.

## مكتمل ومثبت

الواجهة العربية RTL ومسارات لوحة التحكم وسجل التراخيص والأرشيف والإضافة والتعديل والطباعة والمعايرة والسلة والفريق موجودة. الإدخال اليدوي لرقم الترخيص محفوظ، ورقم الأرشفة يولد خادمياً بصيغة آخر أربعة أرقام + تسلسل أربع خانات + `ص`/`م`. توجد قيود منع التكرار وإعادة الاستخدام، صلاحيات مدير، Audit Log، Soft Delete، PWA وطابور Offline.

مختبر Supabase Development المنفصل يحتوي على PostgreSQL وRLS وRPC وTriggers وIdempotency واختبارات CRUD بحسابات اصطناعية. أضيفت له واجهة مختبر مستقلة ومسار Offline→Online متصفحي. نتائج الاختبارات الأخيرة الموثقة قبل جولة التحسين هي TypeScript ناجح، 37 ملف اختبار و104 اختبارات ناجحة، Build ناجح، و`pnpm audit --prod` بلا ثغرات معروفة.

## غير مكتمل أو يحتاج تحسيناً

الصفحات التشغيلية الرئيسية ما زالت تعتمد على Express/tRPC/MySQL؛ مسار Supabase الجديد مختبر انتقال مستقل وليس تحويلة كاملة. جسر Supabase الحالي أضيق من الراوتر التشغيلي في Pagination وExport وDashboard، ويستخدم حد قراءة 100 صفاً وفلترة نصية في العميل لمسار المختبر.

يلزم قياس وتحسين حجم الحزمة وتقسيمها دون تغيير السلوك، ثم إعادة TypeScript وVitest وBuild وAudit. يلزم كذلك اختبار قبول للصفحات التشغيلية على سطح المكتب والجوال مع الحفاظ على RTL والطباعة الرسمية، دون إنشاء بيانات حقيقية.

## معطل فعلياً أو مقيد

لا يوجد عطل تشغيل مؤكد في الفحص الأولي. تحذير حماية كلمات المرور المسربة في Supabase Development متوقع لأن الخيار غير متاح في الخطة المجانية، ولا توجد موافقة على ترقية. لا توجد Cloudflare Pages أو Workers للنشر التجريبي، ولا ينبغي إنشاؤها في هذه المرحلة.

## بيانات تجريبية وحدود البيانات

بيانات Supabase المستخدمة اصطناعية فقط. لا توجد موافقة لاستخدام بيانات Production ولا ينبغي نقلها. لا ينشئ هذا العمل Storage أو مستندات جديدة.

## ما يحتاج Backend وقاعدة وصلاحيات

الانتقال الكامل يحتاج تصميم عقد Supabase مكافئ لكل عمليات Dashboard وList وArchive وTrash وRestore وExport وAudit، ثم تشغيله خلف RLS وRPC قبل تبديل أي صفحة. حذف MySQL/tRPC غير مسموح في هذه المرحلة. جميع عمليات تعديل رقم الأرشفة يجب أن تبقى مديراً فقط مع سبب وسجل تدقيق.

## ترتيب التنفيذ المحافظ

1. جرد الصفحات وعقودها، ثم تحديد فجوات النقل.
2. تحسين الحزمة وقياسها دون تغيير الوظائف.
3. اختبار الصفحات والتحسينات بصرياً وبرمجياً في Development فقط.
4. توثيق خطة النقل التدريجية ومخاطرها وخطوات النشر المستقبلية دون تنفيذ نشر.
5. حفظ نقطة استعادة وتسليم تقرير نهائي.
